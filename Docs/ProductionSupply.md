# 生产输出口与原版生产直供

在魔法存储分类建造“生产输出口”，并用存储线接入具有唯一控制核心的网络。暂用存储接收器贴图。

普通原版/Mod 工作台无需额外组件。同地图中存在生产输出口且可工作的魔法存储网络均可提供库存材料，不受工作台取料半径限制。不同网络的材料可以参与同一批选料，也可以与原版找到的地图材料组合；原版地面取料仍遵循原有半径。

配方、清单筛选、技能、工作量、品质、半成品、消耗回调以及产物去向继续使用原版规则。存储材料直接交付到原版备料位置；地面材料仍按原版流程搬运。

## 接入范围

- 支持使用原版 `DoBill` / `JobDriver_DoBill` 的普通 `Building_WorkTable`，包括没有改写这条任务路径的 Mod 工作台。
- 不接管手术、自主工作台、机械体培育器，以及魔法存储原有的宇宙制作/培育供料。
- 网络使用 `HasProductionOutputPort` 布尔值记录输出口的存在性。拓扑添加节点时设置，失效时清除，合并和分裂时随组件重建。该值由拓扑派生，无须单独存档；供料查询直接读取它，不遍历输出口。
- 供料网络须在同一地图、属于玩家、有唯一控制核心且可工作。待办供料计划绑定来源核心，不绑定某个具体输出口；移除一个输出口后，只要网络仍有其他输出口，后续任务仍可供料。
- 材料须满足配方与清单对实际物品的筛选条件；禁止、不可预留、来源不可用的材料不参与供料。
- 原版选料器直接读取堆数，因此已被其他出库任务部分预留的堆暂不加入候选，避免夸大可用量。不会临时改写真实物品的堆数。
- 备料位置使用原版顺序，选择可达、可预留且没有物品的格子。避免与已有堆合并，也避免向其他存储建筑的收货格投料。没有足够位置时，任务不会出库。

## 生命周期

1. `TryFindBestBillIngredients` 建立只读查询范围；在 `TryFindBestBillIngredientsInSet` 中为本次调用复制并扩充候选列表，继续执行原版选料算法。异常 finalizer 恢复嵌套查询状态。
2. `TryStartNewDoBillJob` 返回真正的原版生产任务后，将存储材料移入独立供料计划。原版搬运队列只保留地面材料，任务定义和驱动均不替换。
3. `TryMakePreToilReservations` 原版预留成功后，区分未来任务的只读预检与 `pawn.CurJob` 正式启动。预检不出库；正式启动时重新核验计划，用现有 `StorageMaterialTransaction` 批量预留和出库。拆分为合法物理堆，建立普通及物理交互预留，再通过 `HaulAIUtility.UpdateJobWithPlacedThings` 登记备料。
4. 全批交付成功后销毁待办计划，后续只保留原版 `job.placedThings`。制作及中断处理归原版管理，不额外退款或收回半成品。
5. 交付失败时，仅回收仍能确认归本次交付管理的实际物品，解除本次预留并交给原有事务恢复；不重建被外部回调销毁的材料。来源不可用的剩余实物保存在已有可存档恢复容器中。

待办计划通过专用 `MS_productionSupply` 节点随 `Job.ExposeData` 保存来源核心、实际材料及数量，复制任务时复制只读计划，任务池 `Clear` 时清理附加状态。待办计划不拥有实物，也不持有跨帧出库预留。

没有修改通用寻路、拾取、背包、拆分、销毁或产物搬运接口。仍需在实际 Mod 组合中验证是否有其他补丁替换相同生产入口。

## 验证

`Tests/VanillaBillSupplyTests.csproj` 链接真实供料、事务和转移源码，使用受控游戏边界验证网络布尔值准入、忽略取料半径、查询无副作用、混合地面材料、任务身份、原版预留、争抢、中断前失效、交付异常、超堆拆分、来源消失、待办计划存读档和任务复制。它不执行原版选料算法、实际寻路、真实存档交叉引用解析或 Harmony 动态补丁。

`StorageFoundationTests` 另外验证真实网络的输出口添加、多个输出口、拆除最后一个、组件合并、分裂、重连和阵营变化时的布尔值更新，并覆盖已有真实网络索引、出库预留、事务恢复及相关生产/搬运逻辑。两个实际游戏版本均需编译；游戏内组合验证由实际运行确认。
